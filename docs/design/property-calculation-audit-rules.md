# Property Calculation 题面通用审计规则

日期：2026-08-21

本文提炼自 `task14-25` 的核对过程，用于后续审查任何 `property_calculation` 题面的 prompt、输入对象和公开答案是否一致、完整、无泄漏。

## 审计顺序

1. 先确认注册位置：题目只能进入 `property_calculation`，不得误落到其他 track。
2. 再核对科学含义：题面是否忠实于原始来源，没有把一个化学问题改成另一个问题。
3. 再核对完整性：约束、单位、目标、输出格式是否都已经写进 prompt。
4. 再查泄漏：gold、计算中间结果、评分/流程元信息是否被写进 prompt。
5. 最后查附件策略：只有原始题目明确要求阅读的 `.xyz` / `.cif` 等内容才允许内联；其他附件默认保留为维护侧证据。

## 必须通过的检查

| 检查项 | 通过标准 | 常见问题 |
|---|---|---|
| Track 注册 | 题目已注册到 `property_calculation`，并且相关 metadata、sample answers、测试都指向同一任务 | 误落到其他 track，或 task / schema / test 不一致 |
| 科学语义 | prompt 保持原始题意，不改变分子、晶体、构象、相态、原子顺序、离子态、计量比等关键含义 | 把原题改写成另一个化学问题，或静默规范化导致语义漂移 |
| 约束完整 | 所有目标、单位、选择规则、输出字段都已明确写出 | 少单位、少输出字段、少“选最低能构象/前三个峰”等规则 |
| 泄漏控制 | prompt 不含 gold、精确中间结果或 evaluator 内部信息 | 直接写出答案、Gaussian 输出、评分内部描述、`expert-validated` 等元信息 |
| 附件使用 | 只把原始题目确实要求答题者读取的附件内容放进 prompt | 把维护侧计算输出或不必要的附件全文搬进题面 |
| 文案清理 | prompt 只保留对解题有用的科学信息 | 重复 SMILES、重复参考块、过程性废话、与任务无关的评分说明 |

## 关键规则

- 常规科学术语（例如相互作用能、结合能、HOMO-LUMO gap、pKa）不需要在 prompt 里再写教科书式定义；只有在原始来源使用了非标准约定，或确实存在多种可能解释时，才补充最小必要说明。
- 只有当“ after geometry optimization ”这类表述是在定义科学状态时才保留；如果某句话只是 benchmark 流程或评分流程描述，就删掉。
- 如果 solver 可以直接从必须内联的 `.xyz` / `.cif` 中识别某个原子、构象或相互作用，就不要在 prompt 里提前替他完成这一步；只保留最小的消歧信息。
- 对于原始来源里的笔误、截断、符号歧义或排版噪声，不要在 prompt 里额外解释它们；要么保留最小可用表述，要么在维护文档中处理，不把问题展开成新的说明文本。
- Gaussian `.out`、CREST 构象输出、评分计算过程等通常只属于维护侧证据，不应进入题面，除非原题明确把它们作为可见输入的一部分。

## 审计结论模板

每道题最终至少记录以下结论：

- 题目是否在正确的 track；
- 题意是否与原始来源一致；
- 约束和目标是否完整；
- 是否存在 gold 泄漏；
- 附件内容是否被合理内联；
- 是否存在冗余、重复或流程性措辞；
- 是否仍有未解决的歧义需要单独确认。

## 通过标准

只有当以上项目全部通过时，才能认为该题的 prompt 审计通过。
