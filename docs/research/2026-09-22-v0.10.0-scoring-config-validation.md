# v0.10.0 Scoring Configuration Validation

Date: 2026-09-22.

The four formal `scoring.yaml` files now contain runtime scoring parameters only.
Profile development `provenance` blocks and property-task `gold_provenance` records were removed. The redundant
`error_mode`, `error_parameter`, and `upper_error_parameter` fields were also
removed from formal profiles because the evaluator never reads them:

- Numeric gold scoring uses `value_transform` for identity, absolute, or log10
  value transformation.
- It uses `lower_tolerance` and `upper_tolerance` as the linear zero-score
  widths, after the optional `minimum_value` domain check.
- Window, target, maximize, and minimize profiles use their `full_score`,
  `full_score_target`, `zero_score_anchor`, and `decay` parameters.

The removed fields duplicated those semantics. `error_mode` duplicated
`value_transform` for numeric gold profiles, and `error_parameter` duplicated a
single tolerance or family calibration input. Neither field was consumed by
`linear_goal_from_profile`, `score_numeric_gold`, or the linear goal kernel.
Research projection scripts were updated to operate on the retained tolerance
fields; historical research documents and calibration records remain outside
formal runtime configuration.
